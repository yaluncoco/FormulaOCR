# FormulaOCR 1.2.0：安装目录与响应速度

## 存储与升级

- EXE 同级 `model/<模型 ID>` 存放 Paddle 和 ONNX 模型；下载断点也在 `model` 中。
- `app` 存放程序依赖、卸载程序、说明文档、设置、日志和运行缓存。默认不在用户目录创建新的 FormulaOCR 数据目录。
- 升级安装移动旧用户缓存和旧 `_internal/models` 中的模型，迁移成功后才删除 `_internal`。源码和便携运行也支持首次迁移；额外源码缓存可通过 `--legacy-cache` 导入。
- 同卷移动使用重命名；跨卷先复制并核对 SHA-256，成功后移除原文件。文件冲突保留在 `app/migration-conflicts`，失败不写完成标记，下次可以重试。
- 安装器显式使用当前安装位置，避免继承测试环境变量后迁错目录。运行时仍允许用户显式设置 `FORMULA_OCR_DATA_DIR`。
- 卸载默认保留用户模型、设置和缓存；确认清理后才删除。

## 响应速度

- ONNX 每个会话默认最多使用 4 个计算线程、1 个跨算子线程，关闭空闲线程自旋；`FORMULA_OCR_ONNX_THREADS` 仍可覆盖线程数量。
- 已初始化的识别器复用模型及会话，不再每次重新走模型加载检查。首次使用与下载完整性校验继续保留。
- LaTeX 转换器按需加载，预览转换在后台执行，并缓存最近 128 次转换结果。
- 原图保持完整用于识别；界面使用单独缩略图，窗口调整期间每 60 毫秒最多更新一次图片。
- 模型筛选复用目录大小统计，减少搜索输入时重复遍历磁盘。
- 运行环境窗口在后台检查 Paddle、ONNX Runtime 和 tokenizer，打开与关闭窗口均不等待检查结束。

## 本机对比

2026-10-15，Windows x64 / Python 3.10.21 / ONNX Runtime 1.23.2，使用相同的本地 RapidLaTeXOCR 模型和 `testdata/percent_interval.png`。两个策略各在独立进程中运行一次，均不下载模型：

| 指标 | 旧线程策略 | 新线程策略 |
|---|---:|---:|
| 导入运行库并创建模型会话 | 4.817 秒 | 1.923 秒 |
| 第一次识别 | 0.479 秒 | 0.416 秒 |
| 第二次识别 | 0.361 秒 | 0.392 秒 |
| 随后 1 秒空闲期间的进程 CPU 用时 | 0.344 秒 | 0 秒 |

两次策略返回的识别文本相同。该样例的 RapidLaTeXOCR 输出本身存在误识别，本次未修改模型和精度逻辑。数据是单机单组测试，受系统缓存与负载影响；模型加载明显改善，热识别耗时相近，不代表所有模型都能获得同样加速。可用 `scripts/benchmark_runtime.py` 重复比较两种策略。
